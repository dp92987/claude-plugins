# Формат профиля

Профиль — markdown-файл `profiles/<имя>.md` в каталоге данных плагина
(`${CLAUDE_PLUGIN_DATA}`). Один профиль = один способ вести тикет до PR для
одной команды; репозиториев к нему может быть привязано несколько. SKILL.md
ссылается на разделы по именам, поэтому имена разделов — контракт: не
переименовывай их.

Правило чтения: **нет раздела — нет шага.** Шаг не показывается в чеклисте
partial и не выполняется в full. Поэтому необязательные разделы не заполняются
заглушками: пустой раздел «Ревьюеры» означает «звать некого», а выдуманная
команда призыва упадёт на живом PR.

У факта, снятого с репозитория или сервиса (cloudId, логин бота, шаблон ветки,
подсмотренный в `git branch -r`), стоит дата съёма.

## Обязательные разделы

### `## Jira`

- URL сайта (`https://<site>.atlassian.net`) — сверяется с сайтом из ссылки
  на тикет и подставляется при голом ключе.
- `cloudId` — параметр `getJiraIssue`.

### `## Ветка`

- Базовая ветка (`master`, `main`, …).
- Шаблон имени ветки тикета с примером из репозитория: `PX-1234-short-slug`,
  `feature/PX-1234`, `px-1234_slug`. Slug — 2–4 слова латиницей через дефис по
  сути тикета; ключ — как в Jira, регистр по шаблону.

## Необязательные разделы

### `## Проверка`

Команды, которыми проверяется имплементация, и откуда их запускать: тесты,
линт, генерация кода, если она обязана быть закоммичена. Одна команда на
строку с комментарием, что она проверяет. Без раздела скилл запускает
очевидное из репозитория и называет это в отчёте.

### `## Pre-review`

Кто смотрит дифф до коммита. Каждая строка — ревьюер:

- `субагент: <model id>` — независимый агент Claude с этой моделью
  (`claude-opus-5`, `claude-sonnet-5`, …).
- `codex` — `codex exec review` через локальный Codex CLI; модель и усилие
  берутся из `~/.codex/config.toml` пользователя.

Без раздела pre-review нет: код идёт в коммит после команд «Проверки».

### `## Коммит`

Формат сообщения с примером: `type(scope): PX-1234 subject`, язык subject,
допустимые типы, откуда берётся scope (имя сервиса, каталог). Даёт шаги
«коммит» и «пуш»; без раздела изменения остаются в рабочем дереве.

### `## PR`

Способ создать PR — одно из двух:

- `скилл: <имя>` — установленный у пользователя скилл, создающий PR;
  заголовок и тело пишет он по своим правилам, профиль о теле не знает.
- `gh pr create` — тогда здесь же: формат заголовка, структура тела, базовая
  ветка, draft или нет.

Без раздела PR не создаётся, и призывать некого.

### `## Ревьюеры`

Таблица «имя → команда»; в команде `<pr>` заменяется номером созданного PR,
`<owner>/<repo>` — репозиторием. Известные способы:

| Ревьюер | Команда |
| --- | --- |
| GitHub Copilot | `gh api -X POST repos/<owner>/<repo>/pulls/<pr>/requested_reviewers -f 'reviewers[]=copilot-pull-request-reviewer[bot]'` |
| Claude (GitHub Action по `@claude`) | `gh pr comment <pr> --body '@claude'` |

Текст комментария для Claude — тот, на который настроен workflow репозитория
(`grep -r '@claude' .github/workflows`); у команды может быть принят свой.
Живой человек в эту таблицу не попадает: кого из людей звать — решение автора
по ситуации, а не профиля.
