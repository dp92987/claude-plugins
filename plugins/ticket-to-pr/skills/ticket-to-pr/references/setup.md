# Настройка: профиль и привязка репозитория

Сюда приходят двумя путями: командой `/ticket-to-pr:setup [имя]` и из full или
partial, когда remote текущего репозитория не привязан ни к одному профилю. Во
втором случае после настройки конвейер продолжается с шага 1.

Каталог данных — `${CLAUDE_PLUGIN_DATA}`; без переменной —
`~/.claude/plugins/data/ticket-to-pr-<marketplace>/`. Формат профиля —
`profile-template.md` рядом с этим файлом; прочитай его до начала: имена
разделов — контракт со SKILL.md.

Правило: **спрашивай, не выдумывай.** Профиль — командные решения; снятое с
репозитория предлагается как вариант, а не записывается молча. Чего
пользователь не знает или не хочет — в профиль не пишется: раздела нет — шага
нет.

## Порядок

1. **Существующие профили.** Прочитай `config.md` и `profiles/`. Если
   пользователь настраивает второй репозиторий той же команды, предложи
   привязать его к существующему профилю, а не заводить копию. Имя нового
   профиля: аргумент команды, иначе спроси; по умолчанию предложи
   `<команда>-<продукт>` в нижнем регистре.

2. **Jira** (обязательно). Спроси URL сайта. `cloudId` сними через
   `getAccessibleAtlassianResources` (Atlassian MCP, один ToolSearch); сайтов
   несколько — покажи и спроси, какой.

3. **Ветка** (обязательно). Базовая — `git symbolic-ref --short
   refs/remotes/origin/HEAD`. Шаблон имени — покажи 5–8 свежих веток из
   `git branch -r --sort=-committerdate`, предложи распознанный шаблон и
   спроси подтверждение: в одном репозитории живут несколько команд с разными
   привычками.

4. **Проверка.** Покажи цели `Makefile` (корня и каталога сервиса, если
   монорепо), скрипты `package.json`, `Taskfile` — что нашлось. Спроси, какие
   команды считаются проверкой перед коммитом и откуда их запускать.

5. **Pre-review.** Спроси, кто смотрит дифф до коммита: субагент Claude (и с
   какой моделью — предложи `claude-opus-5` как сильную по умолчанию,
   `claude-sonnet-5` как быструю), Codex, оба, никто. Для Codex проверь
   `codex --version && codex login status` и покажи результат: раздел с
   недоступным ревьюером бесполезен, пока CLI не поставлен.

6. **Коммит.** Покажи 10 сообщений из `git log --format=%s` и предложи
   распознанный формат; спроси подтверждение и язык subject.

7. **PR.** Если среди доступных скиллов сессии есть скилл, создающий PR,
   назови его и предложи; иначе — `gh pr create` и спроси формат заголовка
   и тела. `gh auth status` покажи, чтобы неавторизованный
   `gh` не всплыл на боевом запуске.

8. **Ревьюеры.** Проверь, кого репозиторий умеет призывать:
   - `grep -rl '@claude' .github/workflows` — есть workflow на комментарий;
     фразу триггера возьми из его `if:` и покажи;
   - Copilot — спроси, включён ли в организации; проверить без PR нельзя,
     поэтому запиши логин `copilot-pull-request-reviewer[bot]` с пометкой
     «подтверждается первым живым призывом».
   Для каждого выбранного — команда по таблице в `profile-template.md` и
   «Ответ»: логин, под которым бот отвечает, и срок ожидания. Логин и время
   ответа сними с последних PR, где бот уже отвечал
   (`gh api repos/<owner>/<repo>/pulls/<pr>/reviews`), с датой съёма; таких PR
   нет — значения из шаблона с пометкой «подтверждается первым живым призывом».

9. **Статусы.** Спроси, двигать ли тикет и в какие моменты: перед работой,
   после PR, оба, никогда. Путь сними с живых тикетов проекта: для каждого
   статуса пути найди JQL-ом тикет в нём (`project = <KEY> AND status =
   "<статус>"`) и покажи `getTransitionsForJiraIssue` — у каждого звена должен
   быть переход в следующий статус. Проверь на типах задач, с которыми работает
   команда (Task, Story, Bug), и запиши, на каких проверено.

10. **Запиши профиль** в `profiles/<имя>.md`. У снятых фактов — дата.

11. **Привяжи репозиторий.** `git remote get-url origin`, нормализованный до
    `github.com/org/repo`, — строкой в таблицу `config.md` (создай файл с
    заголовком таблицы, если его нет). Только точные совпадения.

12. **Покажи результат:** путь к профилю, какие шаги он даёт, какие разделы
    пропущены и почему, строка маппинга. Правки внеси сразу.
