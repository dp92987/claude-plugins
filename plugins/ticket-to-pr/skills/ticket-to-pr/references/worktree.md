# Ветка и ворктри

Детали шага 4 SKILL.md. Тикет всегда делается в отдельном ворктри своей ветки;
основной чекаут не трогается.

1. Выбери, где ветка тикета живёт сейчас. Ветка — имя по шаблону, или
   существующая ветка с ключом тикета, если пользователь уже начал.
   - **Сессия уже в ворктри этой ветки** (текущая ветка содержит ключ, и
     `git rev-parse --show-toplevel` — не основной чекаут) — работай в нём.
   - **Ворктри ветки уже есть** — `git worktree list --porcelain` показывает
     запись с `branch refs/heads/<ветка>`: войди в него (шаг 2).
   - **Ветка есть локально, но не выкачана** — `git worktree add <путь>
     <ветка>`.
   - **Ветки нет** — `git fetch origin <база>`, затем `git worktree add
     --no-track -b <ветка> <путь> origin/<база>`. Без `--no-track` upstream
     ветки тикета — база, и голый `git push` в стеке уходит в ветку чужого
     PR; upstream ставит первый `git push -u` (шаг 8). База — из профиля, а
     если на шаге 2
     решили строить на несмерженных PR: стек — ветка PR зависимости
     (`--base` у PR тоже она); сводная — ветка от первой зависимости, в
     которую смержены остальные (PR тогда на базу профиля, draft до их мержа).
   - **Ветка с ключом тикета выкачана в основном чекауте** — не трогай его и
     спроси, переносить ли работу в ворктри: две копии одной ветки git не
     даст, а основной чекаут переключать нельзя.

   Путь профиль не задаёт — это личная настройка пользователя: следуй
   правилам сессии (CLAUDE.md, память, настройки Claude Code). Правила нет —
   каталог, который использует сам Claude Code:
   `<основной чекаут>/.claude/worktrees/<ветка>`. `EnterWorktree` с `name`
   вместо создания руками не годится: он назовёт ветку по-своему, а не по
   шаблону профиля. Путь уже занят чем-то, что не ворктри этой ветки, —
   остановись и покажи, что там лежит.
2. Войди в ворктри: `EnterWorktree` с `path`. Хуки других плагинов (гейт
   перед `gh pr create`) и харнесс смотрят на cwd сессии, а `cd` внутри Bash
   его не меняет: без входа PR проверяется по ветке основного чекаута.
3. Внутри ворктри команды запускай простыми, по одной: составную харнесс
   изоляции отклоняет, раз не может доказать, что она не выходит за ворктри.
   Отказывает в любой команде, не только `git`: на heredoc, `cd … &&`,
   переменной в позиции аргумента, `github.com` в пути (принимает за git вне
   ворктри). Текст и скрипты пиши файлами через Write в
   `~/.cache/<тикет>/` и запускай отдельной простой командой (`bash <файл>`,
   `python3 -I <файл> <аргументы>`); файлы ворктри правь через Edit.
4. Нужно поработать в другом ворктри (база стека, соседняя ветка) — сначала
   `ExitWorktree` с `action: "keep"`, затем `EnterWorktree` с `path` нужного:
   из ворктри вне `.claude/worktrees/` прямой переход в другой харнесс не
   даёт. Обратно — тем же путём.
