# Ревью в PR: ждать и разобрать

Детали шага 12 SKILL.md: призванный ревьюер — обещание разобрать его ревью.

**Ждать.** Колонка «Ответ» профиля говорит, где появляется ответ каждого
ревьюера (ревью или комментарий, логин бота) и сколько его ждать.

- Жди через `Monitor` с циклом, который опрашивает место ответа
  (`gh api repos/<owner>/<repo>/pulls/<pr>/reviews`) и выходит, когда ответил
  каждый призванный ревьюер или истёк срок. Ожидание не опирается на
  наблюдатели PR конкретного хоста: скилл ведёт себя одинаково в любом
  окружении Claude Code. Команду опроса сначала выполни один раз на переднем
  плане и не глуши её stderr: сломанный флаг в цикле молча опрашивает вечно.
  Цикл пиши в файл-скрипт (`~/.cache/<тикет>/wait-reviews.sh`) и запускай
  `Monitor` командой `bash <скрипт>`: в ворктри-изоляции харнесс отказывает
  инлайн-циклам и подстановкам `$(…)` (PX-6194, 2026-10-16).
- Срок вышел, ответа нет — ревьюер идёт в отчёт как промолчавший; дальше не
  ждёшь.
- Ревьюер, который приходит сам, своего срока не задаёт: ожидание кончается
  по призванным (ответили все или вышел их срок). Он к этому моменту не
  пришёл — промолчавший, его не ждёшь. Пришёл — в разбор идут все его
  ревью и комментарии, появившиеся к концу ожидания: такой бот бывает
  отвечает несколькими ревью. Призванных нет вовсе — ждёшь его по сроку из
  «Ответа».
- У ревьюера в профиле нет «Ответа» — его не ждёшь и называешь это в отчёте с
  советом дополнить профиль через `/ticket-to-pr:setup`: срок и место ответа
  по памяти не подставляются.

Перед тем как закончить ход в ожидании, отправь отчёт по шагам 0–11 со
строкой «жду ревью: <кто>, до <время>»: пользователь не должен гадать, работа
идёт или встала.

**Разобрать.** Один проход, без раундов: переговоры о коде уже прошли на
pre-review, а повторный призыв бота приносит новое ревью целиком и раздувает
PR. Каждое замечание — inline-комментарий и пункт общего ревью — разбери по
правилам pre-review (`references/pre-review.md`, «Разбор находок»): сверь с
кодом, блокирующность назначь сам; подтверждённая blocking — самый узкий фикс;
non-blocking — по тем же условиям «бери, только если верно всё»; вне PR —
строка follow-up в отчёте, тикетов не заводишь; не проверено — не чинится и
так и называется. Раз второго круга нет, два правила другие:

- **Спор с ботом — ответ в треде с доказательством** (file:line, тест,
  вывод). Понизить его blocking можно только так, и такая находка идёт в отчёт
  поимённо, как неисправленная blocking pre-review. Доказательства нет —
  чини.
- **Замечание человека — не находка бота.** Его blocking, с которым ты не
  согласен, сам не отклоняешь: это вопрос пользователю, с обеими позициями в
  2–3 строки. Его non-blocking бери по тем же условиям; не подходит — ответ в
  треде с причиной.

К пользователю из ревью в PR идёт то же, что из pre-review («Когда к
пользователю»), плюс несогласие с blocking человека.

- Исправления: шаг 5а, шаг 5б — если исправление задело код, которым
  доказан критерий, затем отдельный коммит по формату
  «Коммит» поверх ветки и пуш без `--force`. В отличие от pre-review, историю
  PR ревьюеры уже видели, и переписывать её нельзя.
- В треде каждого замечания — ответ с исходом: исправлено (короткий sha),
  отклонено и почему (с доказательством), вне PR — follow-up в отчёте. Ответ только в чате не
  считается: следующий читатель PR видит тред, а не сессию. Треды, закрытые
  исправлением, резолвь. Форма — одна команда на тред: GraphQL-документ с
  `addPullRequestReviewThreadReply` (`pullRequestReviewThreadId`, тело —
  из файла, записанного Write) и следом `resolveReviewThread` с тем же
  литеральным id треда; id — из видимого запроса `reviewThreads` к
  литеральным owner/repo/номеру PR. Классификатор auto mode видит команды,
  а не их вывод: цикл резолва по всем тредам из ответа API он отклоняет,
  а ответ и резолв одного треда в одной команде связаны на виду (PX-6238,
  2026-10-22).
- Исправление изменило поведение, описанное в теле PR или в тикете, —
  обнови их в том же проходе: PR — способом из раздела «PR», тикет —
  `editJiraIssue`. Иначе один из них остаётся с устаревшим утверждением.
