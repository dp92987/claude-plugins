# worktree-janitor

Отчёт по git worktrees и их безопасное удаление.

Запускается только явно:

```
/worktree-janitor:worktrees [каталог] [--clean]
```

Без каталога берётся текущий. Без `--clean` скилл только отчитывается.
Автоматически по упоминанию worktree он не включается — замеры показали, что
модель и так решает эти задачи сама, поэтому автосрабатывание отключено намеренно.

Скилл находит все worktrees в указанном каталоге (или в текущем), определяет
состояние каждого и группирует их по тому, можно ли потерять лежащую внутри
работу:

- `dirty` — незакоммиченные файлы;
- `local-only` — коммитов нет ни на upstream, ни в дефолтной ветке;
- `pushed` — работа на remote, но не в дефолтной ветке;
- `merged` — работа уже в дефолтной ветке, в том числе через squash-merge;
- `empty` — коммитов сверх дефолтной ветки нет.

Главная причина существования скилла — `git cherry` не видит squash-merge и
показывает влитую ветку как уникальную. Скрипт `scripts/scan_worktrees.py`
сравнивает patch-id суммарного дифа ветки с коммитами дефолтной ветки и ловит
этот случай.

Удаление — отдельный шаг по явной просьбе. Ветки и коммиты скилл не трогает,
`--force` не использует.

## Использование

```
python3 skills/worktree-janitor/scripts/scan_worktrees.py [КАТАЛОГ] [--json]
```
