# Формат профиля

Профиль — markdown-файл `profiles/<имя>.md` в каталоге данных плагина
(`${CLAUDE_PLUGIN_DATA}`). Один профиль = один Jira-проект одной команды.
SKILL.md ссылается на разделы профиля по их именам, поэтому имена разделов —
контракт: не переименовывай их.

Правило чтения: **нет раздела — скилл этим полем не управляет.** Поэтому
необязательные разделы не заполняются заглушками «на потом»: пустой или
выдуманный раздел хуже отсутствующего.

Каждый факт профиля снят с живого проекта, и рядом стоит дата съёма. Профиль без
дат деградирует до догадок: через полгода нечем понять, чему ещё можно верить.

## Обязательные разделы

Без них скилл не может создать даже минимальный тикет.

### `## Сайт`

- URL сайта (`https://<site>.atlassian.net`) — из него собирается ссылка на
  тикет в отчёте.
- `cloudId` — параметр каждого вызова MCP.

### `## Jira-проект`

- Ключ проекта (и, если известен, id).
- Статус, в котором создаётся тикет (информационно: скилл статусами не
  управляет).
- Есть ли в проекте подзадачи.

### `## Язык`

Язык заголовка и тела описания. Идентификаторы из кода остаются как есть при
любом языке.

### `## Типы задач`

Таблица «имя — id — для чего» плюс два умолчания: тип для любой работы и тип
для дефекта. `createJiraIssue` принимает имя типа; id нужны только setup.

## Необязательные разделы

### `## Кастомные поля`

Id полей Story Points, Sprint, Epic Link и особенности экранов создания: у
какого типа поля нет на экране (ставится вторым вызовом `editJiraIssue`), у
какого поле имеет умолчание. Без раздела скилл не ставит ни оценку, ни спринт,
ни Epic Link.

Id поля Story Points включает оценку: скилл оценивает по встроенной шкале из
SKILL.md даже без раздела «Оценка».

### `## Компоненты`

Список компонентов проекта и компонент по умолчанию. Без раздела компонент не
ставится.

### `## Лейблы`

Командные правила: какие лейблы существуют, сколько их у тикета, как выбирать.
Без раздела лейблы не ставятся.

### `## Продуктовые проекты`

Как команда называет свои кодовые базы и во что имя продуктового проекта
превращается в полях тикета (обычно — в лейбл). Снимает двусмысленность «заведи
задачу в проекте X», когда X — не ключ трекера.

### `## Заголовок`

Командный формат заголовка: префиксы, их порядок, правила сокращения имён.
Без раздела заголовок пишется без префиксов.

### `## Оценка`

Командное уточнение встроенной шкалы из SKILL.md: примеры команды, ссылка на её
статью, другие типы задач с оценкой, при желании — своя шкала и свои сигнальные
значения. В той части, которую раздел задаёт, он выигрывает у умолчания. Без
раздела действует встроенная шкала; саму оценку включает id поля Story Points в
«Кастомных полях».

### `## Спринты`

Id поля спринта, id доски, пример живого значения. Без раздела спринт не
ставится даже по явной просьбе — скилл скажет, что поля не знает.

### `## Связи`

Тип и направление связи «стори → задача» (обычно `Work item split`), таблица
остальных типов связей с id и подписями inward/outward. Без раздела скилл не
создаёт связей и говорит об этом в отчёте.

### `## Проверенные особенности сайта`

Измеренные факты про конкретный сайт: объём ответов метаданных, несоблюдение
`fields` и подобное. Каждый — с датой.
