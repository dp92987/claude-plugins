# Поведение Atlassian MCP

Файл описывает поведение сервера, одинаковое для любого сайта Jira. Все id и
значения конкретного проекта — в профиле (см. SKILL.md, шаг 0); здесь ключи и
id в примерах — заглушки.

## Метаданные не тянуть

Если Jira отвечает «field cannot be set», не тяни метаданные экрана создания:
ответ `getJiraIssueTypeMetaWithFields` по одному проекту — это сотни тысяч
знаков (у измеренного проекта — около 240 тысяч), он вытеснит из контекста саму
задачу. Создай тикет без спорного поля, скажи пользователю, какое поле Jira
отклонила, и предложи поставить его руками.

Id полей, типов и связей берутся из профиля, а не запросом метаданных. Полей
нет в профиле — это работа для `/jira-ticket-creator:setup`, не для основного
флоу.

## Эпик стори

Стори задаёт новому тикету не только связь, но и эпик — тот же, в котором лежит
она сама. Читается одним вызовом до создания:

```json
{"cloudId": "…", "issueIdOrKey": "ABC-5512", "fields": ["parent"]}
```

**Ограничение по `fields` сервер не соблюдает** (проверено 15.08.2026).
Вернётся набор по умолчанию: `summary`, `issuetype`, `parent`, `project`,
`description`, `assignee`, `status`, плюс развёрнутый `parent` и блок
`context`. Несколько тысяч знаков ради семи полезных. Дешевле не получается —
поэтому вызов делается только тогда, когда эпик не назван пользователем.

Полезное в ответе одно: `parent.key`. Описание стори не переиспользуй.

## Поиск id спринта по имени

Поле спринта принимает числовой id, а не строку. Точное имя превращается в id
одним вызовом (ключ проекта и id доски — из профиля):

```
searchJiraIssuesUsingJql:
  jql: "project = <KEY> AND sprint in openSprints() ORDER BY updated DESC"
  fields: ["<id поля Sprint из профиля>"]
  maxResults: 5
```

В ответе поле спринта — массив объектов со `id`, `name`, `state`, `boardId`,
`startDate`, `endDate`. Массив содержит и **закрытые** спринты тикета, поэтому
ищи по `name`, а не по позиции, и сверяй `boardId` с доской из профиля.
Названного имени в выдаче нет — спроси id, а не подставляй похожее: запрос
находит только спринты, куда уже что-то положено, и пустой спринт им не увидеть.

Ставь спринт при создании. Если Jira отклоняет поле на экране создания, проставь
его после через `editJiraIssue` тем же значением; при отказе на числе попробуй
массив (`[12345]`).

## Проверка результата

Ответ на создание содержит **не все** поля: у `editJiraIssue` схема прямо говорит,
что возвращается дефолтный набор чтения (summary, description, status, issuetype,
priority, labels, components, assignee, reporter, resolution, project), а `parent`,
оценка и спринт в него не входят. Состав ответа `createJiraIssue` схемой не
обещан вовсе.

Отсюда правило: то, что видно в ответе, сверяй по ответу. Про остальное не
утверждай, что оно проставилось. В отчёте пиши как есть — «передан `parent`
ABC-3480, подтверждение не запрашивал», — и не выдумывай подтверждения, которого у
тебя нет.

Один читающий вызов `getJiraIssue` оправдан, только когда цена ошибки выше цены
шума: тикет уходит в спринт, который вот-вот берут в работу, или связь с эпиком
критична для отчётности. По умолчанию его не делай.

## Правка существующего тикета

`editJiraIssue` перезаписывает `description` целиком — операции «дописать» у него
нет. Поэтому новую версию текста нужно собрать целиком, показать пользователю и
дождаться «да».

Текущий текст берётся так:

| Чей тикет | Откуда текст |
| --- | --- |
| создан в этой сессии | из контекста: ты сам его писал, читать нечего |
| чужой или из прошлой сессии | `getJiraIssue` с `fields: ["summary","description"]` и `responseContentFormat: "markdown"` |

Во втором случае чтение обязательно: без него правка не дописывает, а стирает.

## Если запрос падает

**Cloudflare-страница «Attention Required!» вместо JSON.** WAF перед
MCP-эндпоинтом реагирует на код в теле запроса (curl, mongosh, JSON). Это
подтверждено на Confluence; на описании тикета с большим блоком кода возможно то
же.

Повтори вызов один раз: часть срабатываний разовые. Если повторилось — создай
тикет **без блока кода**, оставив на его месте строку «фрагмент кода — в
комментарии», и отдай блок пользователю, чтобы он вставил его руками. Не
экранируй код HTML-сущностями: при `contentFormat: "markdown"` они не
декодируются, и в тикете останется литеральный `&lt;`, то есть неверный код —
это хуже отсутствующего фрагмента.

**Поле отклонено.** Создай тикет без спорного поля и скажи пользователю, какое
поле Jira не приняла. Метаданные экрана создания не тяни (см. начало файла).

**MCP не подключён.** Порядок действий — в SKILL.md, шаг 6: отдать пользователю
готовый текст, ничего не имитируя.
