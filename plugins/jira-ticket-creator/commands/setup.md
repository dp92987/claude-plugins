Создай профиль Jira для скилла jira-ticket-creator или обнови существующий,
затем привяжи к нему текущий репозиторий.

Каталог данных — `${CLAUDE_PLUGIN_DATA}`; если переменная не подставлена, ищи
`~/.claude/plugins/data/jira-ticket-creator-<marketplace>/`. Формат профиля —
`${CLAUDE_PLUGIN_ROOT}/skills/jira-ticket-creator/references/profile-template.md`.
Прочитай его целиком до начала: имена разделов — контракт со SKILL.md.

## Порядок

1. **Существующие профили.** Прочитай `config.md` и список `profiles/`. Если
   профиль для нужного сайта и проекта уже есть, предложи обновить его, а не
   создавать дубль.

2. **Обязательное — спроси у пользователя:** сайт (URL), ключ Jira-проекта,
   язык тикетов. Имя профиля: аргумент команды, иначе `<сайт>-<ключ>` в нижнем
   регистре (например, `mycorp-abc`).

3. **Обязательное — сними с Jira.** Загрузи схемы одним вызовом ToolSearch:
   `getAccessibleAtlassianResources` (cloudId по URL сайта),
   `getVisibleJiraProjects` (id проекта), `getJiraProjectIssueTypesMetadata`
   (типы и их id), `getIssueLinkTypes` (типы связей).

   WARNING: `getJiraIssueTypeMetaWithFields` по всему проекту не вызывай — ответ
   занимает сотни тысяч знаков. Если id кастомных полей нужны, спроси у
   пользователя ключ одного типового тикета с заполненными оценкой, спринтом и
   эпиком и прочитай его одним `getJiraIssue`: id полей видны по значениям.

4. **Командные умолчания — спроси, не выдумывай:** компонент по умолчанию и
   список компонентов, правила лейблов, формат заголовка, доска спринтов;
   шкала оценки — только если командная отличается от встроенной в SKILL.md
   (у скилла есть шкала по умолчанию, оценку включает id поля Story Points). Пользователь не знает или раздел не
   нужен — раздел не пишется: скилл тогда этим полем не управляет. Заглушек в
   профиле не бывает.

5. **Запиши профиль** в `profiles/<имя>.md` по шаблону. У каждого снятого с
   Jira факта поставь сегодняшнюю дату съёма.

6. **Привяжи репозиторий.** Возьми `git remote get-url origin` текущего
   каталога, нормализуй до `github.com/org/repo` и добавь строку в таблицу
   маппинга `config.md`. Маппинг знает только точные совпадения: другой
   репозиторий той же команды привязывается своей строкой к тому же профилю.

7. **Покажи результат:** путь к профилю, что в нём заполнено, что пропущено и
   почему, строка маппинга. Правки пользователя вноси сразу.
